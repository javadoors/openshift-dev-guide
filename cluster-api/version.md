# Cluster-API 版本与 K8s 版本配套关系

## 一、版本支持策略

### 1.1 CAPI 发布支持策略
| 规则 | 说明 |
|------|------|
| **活跃支持** | 最新两个 minor 版本 (N, N-1) |
| **维护模式** | N-2 版本，仅紧急修复 |
| **EOL** | N-3 及更早版本，不再支持 |
| **发布周期** | 约每 4 个月发布一个新 minor 版本 |

### 1.2 Kubernetes 版本支持策略
| 集群类型 | 初始支持范围 | 新 K8s 发布后扩展 |
|----------|-------------|------------------|
| **管理集群** | N ~ N-3 (4 个版本) | N ~ N-4 (5 个版本) |
| **工作负载集群** | N ~ N-5 (6 个版本) | N ~ N-6 (7 个版本) |

## 五、版本倾斜策略

### 5.1 CAPI 升级跳跃限制
| 规则 | 说明 |
|------|------|
| **最大跳跃** | 最多跳过 3 个 minor 版本 |
| **示例** | v1.6.x → v1.9.x (允许)，v1.5.x → v1.9.x (不允许) |
| **降级** | 不支持版本降级 |

### 5.2 Provider 版本倾斜
| 规则 | 说明 |
|------|------|
| **Contract 匹配** | 所有 Provider 必须实现相同的 Contract 版本 |
| **版本号独立** | Provider 版本号不需要与 CAPI 版本号匹配 |
| **clusterctl 保证** | `clusterctl` 会自动确保所有 Provider 版本兼容 |

### 5.3 K8s 组件版本倾斜
遵循 [Kubernetes Version Skew Policy](https://kubernetes.io/releases/version-skew-policy/)：

| 组件 | 最大版本差 |
|------|-----------|
| kube-apiserver ↔ kubelet | ±1 minor |
| kube-apiserver ↔ kube-proxy/coredns | ±1 minor |
| kubeadm ↔ kubelet | ±1 minor |

## 六、部署模型与版本支持

### 6.1 管理集群/工作负载集群分离 (推荐)
```
管理集群 (K8s v1.32)          工作负载集群 (K8s v1.30)
┌─────────────────┐          ┌─────────────────┐
│ CAPI v1.12      │ ──────── │ 被管理的集群     │
│ 控制器运行中     │          │ 可以是不同 K8s   │
└─────────────────┘          └─────────────────┘
```
- 管理集群和工作负载集群可以运行不同的 K8s 版本
- 升级可以独立进行

### 6.2 自托管集群 (Self-hosted)
```
自托管集群 (K8s v1.32)
┌─────────────────────────────────┐
│ CAPI v1.12 控制器运行在集群内    │
│ 同时管理自身和其他工作负载集群    │
│ K8s 版本受管理集群支持范围限制    │
└─────────────────────────────────┘
```
- K8s 版本受限于管理集群支持范围

## 七、K8s 特定版本注意事项

### K8s v1.36 (即将发布)
- `ControlPlaneKubeletLocalMode` 特性门控毕业为 GA 并被移除
- CAPI 将不再显式设置此特性门控

### K8s v1.31
- 不再支持连续应用 `caBundle: Cg==` 的 CRD
- kubeadm 移除 `control-plane update-status` 阶段
- 引入 `ControlPlaneKubeletLocalMode` 特性门控 (CAPI 自动启用)

### K8s v1.29
- 树内云提供商默认禁用
- 如需使用需设置 `DisableCloudProviders` 和 `DisableKubeletCloudCredentialProvider` 特性门控

## 八、推荐版本组合
| 场景 | CAPI 版本 | 管理集群 K8s | 工作负载集群 K8s |
|------|----------|-------------|-----------------|
| **最新稳定** | v1.13.x | v1.32 ~ v1.35 | v1.30 ~ v1.35 |
| **生产推荐** | v1.12.x | v1.31 ~ v1.34 | v1.29 ~ v1.35 |
| **保守选择** | v1.11.x | v1.30 ~ v1.33 | v1.28 ~ v1.34 |
| **升级过渡** | v1.12.x → v1.13.x | v1.32 → v1.33 | v1.30 → v1.31 |

## 九、升级路径示例
```
当前状态:
  CAPI v1.11 + K8s v1.30 (管理) + K8s v1.28 (工作负载)

推荐升级路径:
  1. 升级 clusterctl 到 v1.12.x
  2. 升级管理集群 K8s: v1.30 → v1.31
  3. 升级 CAPI: v1.11 → v1.12
  4. 升级工作负载集群 K8s: v1.28 → v1.30
  5. (可选) 继续升级到 CAPI v1.13 + K8s v1.32+
```
