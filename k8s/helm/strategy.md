# 策略配置
配置片段：  
```yaml
strategy:
    wait: true           # Helm SDK 原生等待
    waitTimeout: "5m"
    atomic: true
```
这是 Helm 在执行安装/升级时的 **策略配置**，它结合了等待、超时和自动回滚机制。  

## 📌 各字段作用
- **wait**：  
  - 启用后，Helm 会等待所有相关的 Kubernetes 资源（如 Pod、Service、Deployment）进入就绪状态。  
  - 默认行为是立即返回，不保证资源已 Ready。  
- **waitTimeout**：  
  - 设置等待的最大时长，这里是 5 分钟。  
  - 如果超过时间资源仍未就绪，Helm 会判定失败。  
- **atomic**：  
  - 启用后，如果安装/升级失败，Helm 会自动回滚到之前的 release 状态。  
  - 保证集群不会处于“半成功半失败”的不一致状态。  

## 🏗️ 整体效果
- Helm 会在安装/升级时：  
  1. 等待资源进入就绪状态（最长 5 分钟）。  
  2. 如果超时或失败，触发自动回滚。  
  3. 成功则提交所有更改。  

## ⚠️ 注意事项
- **有状态应用风险**：即使 `atomic` 回滚，PVC/数据库等有状态资源的数据不会自动恢复。  
- **调试难度**：失败后资源会被清理，可能不利于排查问题。  
- **生产环境推荐**：这种配置适合生产环境，保证一致性；测试环境可关闭 `atomic`，方便调试。  

✅ **总结**：这段配置的含义是：Helm 在安装/升级时会等待资源就绪（最长 5 分钟），如果失败则自动回滚，确保集群状态一致。
