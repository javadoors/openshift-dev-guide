# *Prune（裁剪）
在 Kubernetes 中，**Prune（裁剪）** 的作用是：当你应用一份清单（manifest）时，自动删除集群中那些 **不再出现在清单里** 的资源，保持集群实际状态与声明式配置一致。  

## 📌 Prune 的核心机制
- **对比现有资源**：kubectl 会根据 label 选择器找到当前已存在的资源。  
- **删除未声明资源**：如果某个资源在集群中存在，但在新的清单中没有定义，就会被删除。  
- **保持声明式一致性**：避免遗留资源继续运行，保证集群状态与配置文件完全一致。  

## 🏗️ 使用示例
```bash
kubectl apply -f manifests/ --prune -l app=myapp
```
- `--prune`：启用裁剪功能。  
- `-l app=myapp`：只裁剪带有该 label 的资源。  

## 📊 适用场景与风险

| **场景** | **效果** | **风险点** |
|----------|----------|------------|
| **GitOps** | 保证集群状态与 Git 仓库一致 | 误删未在 Git 中声明的资源 |
| **CI/CD 部署** | 自动清理旧版本资源 | Label 选择器不当可能误删 |
| **多团队共享集群** | 保持团队资源隔离 | 如果 label 不精确，可能影响其他团队 |

## ⚠️ 注意事项
- **必须加 label 选择器**：否则可能误删整个命名空间的资源。  
- **不适合有状态资源**：如 PVC、数据库 StatefulSet，Prune 删除后数据不可恢复。  
- **调试环境慎用**：可能导致资源被意外清理，影响排查。  
- **推荐 GitOps 场景**：与 ArgoCD、Flux 等工具结合，保证声明式一致性。  

✅ 总结：**Prune 的作用是裁剪掉未在清单中声明的资源，保证集群状态与配置一致。它适合 GitOps 和 CI/CD 部署场景，但对有状态资源需谨慎使用，避免误删数据。**
